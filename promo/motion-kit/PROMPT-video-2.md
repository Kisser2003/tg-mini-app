## Продукт и код
omf — Telegram Mini App: артист заполняет паспорт релиза, загружает обложку и WAV, отправляет на модерацию; модератор принимает или возвращает с причиной.
Репозиторий: github.com/Kisser2003/tg-mini-app, ветка `claude/ecstatic-clarke-3b94n6`. Все экраны, тексты и анимации бери из кода этой ветки, ничего не придумывай.

## Тема видео 2: «Всегда понятно, что дальше»
Хук (первые 1,5 с): «Больше никаких „а что с моим релизом?“».
Сцены (черновик, уточни по коду и ритму трека):
1. Библиотека «Твои релизы»: под каждой плиткой цветная строка следующего шага. Реальные тексты из `lib/release-next-step.ts`: «Допиши и отправь», «Осталось отправить», «На проверке 3 ч», «Дольше обычного», «Исправь замечания», «Ссылка готова». Покажи их по очереди крупными планами (камера переезжает от плитки к плитке на бит).
2. Сверху блок «Нужно твоё действие» со строками «Релиз вернули → Исправить» и «2 релиза не отправлены → Открыть».
3. Тап по релизу → экран релиза (`app/release/[id]`): большой конверт с наклейкой статуса, под ним блок статуса (title/body из `getReleaseNextStep`) и кнопка «Продолжить».
4. Финальная карточка 2 с: «omf · выпуск музыки прямо из Telegram» + @OMF_Distribution_BOT.
Длина 15–25 с, 9:16, 1080×1920, 30 fps.

## Визуальный стиль серии (как видео 1 — не менять)
- Фон ролика почти чёрный hsl(240 5% 4%), один мягкий синий радиальный свет, виньетка, анимированное плёночное зерно (6 заготовленных шумовых кадров 540×960, растянуты на кадр, смена 24 раза в секунду, два слоя: screen 0.11 и multiply 0.10).
- Текст ролика: системный шрифт (-apple-system / SF), вес 600, letter-spacing −0.045em. Хук двумя строками: первая белая, вторая серая hsl(240 3% 62%). Над экраном только маленькая серая подпись сцены (32 px). Без жёлтого, без неона, без эмодзи в подписях.
- Экран приложения — плоская карточка 390×894 (сверху шапка Telegram 50 px: «✕ Закрыть» цветом #6ab3f3, по центру «omf / мини-приложение», справа кружок «⋯»; ниже экран приложения 390×844), скругление 30 px, масштаб ×1.5, тень. Рамку телефона не рисовать.
- Камера: в моменты действия приближай карточку к нужному месту (зум 1.2–1.75) и возвращай к общему плану; движения камеры по кривой приложения cubic-bezier(0.22, 1, 0.36, 1).
- Смены сцен — короткий провал через фон (размытие + затемнение ~0.3 с), без грязных наложений.
- Тап — белый кружок-касание. Вибрацию показывать маленькой плашкой «вибрация» с иконкой у пальца, только там, где в коде есть haptic.
- На клэпах трека — лёгкий пульс камеры (scale +0.8%) и свечения.

## Техника: в кадре настоящее приложение, а не перерисовка
Готовый набор лежит в `promo/motion-kit` (README, скрипты, образец видео 1, обложки) — начни с него, ниже кратко то же самое.
1. Подними приложение из ветки (`npm ci`, `next dev`) с `NEXT_PUBLIC_ALLOW_DEV_API_AUTH=true`, заходи с `?devUserId=1`. Боевую базу не трогай: в Playwright перехватывай `**/api/releases/my**` и другие `/api/releases/*`, которые нужны экрану, и отдавай фейковые релизы (`{ ok: true, rows: [...] }`). Обложки подставляй как data:URL (тогда next/image их не оптимизирует).
2. Снимай каждое нужное состояние экрана через Playwright (390×844, DPR 2, isMobile, hasTouch): скриншот для проверки + снимок DOM (`body.innerHTML` без скриптов) + весь CSS (`document.styleSheets → cssRules`). Плашку ошибок Next (`nextjs-portal`) скрывай.
3. Подготовка CSS для сборки:
   - `@font-face` вынеси в основной документ, файлы шрифтов скачай с `/_next/static/media/`;
   - `:root` → `:host`, селекторы `html`/`body` → `.shroot`;
   - заморозь мобильную раскладку: `(min-width: N px)` при N > 390 → никогда не срабатывает, при N ≤ 390 → всегда; `vh`/`vw` → px от 844/390;
   - добавь `.shroot{background:var(--omf-bg)}`.
4. Сборка: каждый экран — свой shadow root внутри карточки (`contain: layout paint; transform: translateZ(0)`, чтобы fixed-элементы вроде нижнего меню жили внутри экрана). Вкладку «Модерация» из нижнего меню удали (артист её не видит).
5. Анимации проигрывай покадрово, кадр = чистая функция времени:
   - CSS-анимации приложения (`omf-stagger-in`, `omf-sticker-slap`, `omf-page-enter`, `omf-step-enter`, `omf-cover-in`, `omf-reveal`) — `shadowRoot.getAnimations()`, `pause()`, каждый кадр `currentTime = локальное время экрана`. Если экран снят прямой загрузкой, классы перехода (`omf-page-enter` на `.min-h-app.overflow-x-hidden`) добавь сам — их приложение ставит при навигации;
   - пружины framer-motion считай аналитически (масса 1): пилюля фильтров 520/40, индикатор таба 500/40, шторки SPRING_UI 300/30. Родные `layoutId`-спаны скрой, рисуй свои;
   - точные тайминги бери из кода: `app/globals.css` (keyframes, `--omf-ease-out`), `SuccessReleaseModal`, `CreateStepTransition`, `ReleaseSleeve`.
6. Рендер: headless Chrome, 30 fps, motion blur — 4 подкадра на кадр с затвором 0.5 и усреднение ffmpeg `tmix`; 6 воркеров по чанкам. Сначала стопкадры всех сцен и середин переходов, потом полный рендер (~8 мин на 23 с).
7. Финал: постер (устоявшийся кадр) вшить в нулевой кадр без добавления кадров, сжать до ~50 МБ (`crf 20`, `maxrate 12M`), `share-copy.txt` на 1–3 предложения без непроверенных фактов.
